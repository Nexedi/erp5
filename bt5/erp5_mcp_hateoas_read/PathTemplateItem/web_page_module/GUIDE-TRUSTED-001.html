Write trusted code: Module / Extension Components vs the sandbox

Skin scripts and portal_callables MCP tools run inside Zope's restricted sandbox: no open/os/subprocess, guarded imports, and getattr of underscore names (e.g. __of__) is refused. When a tool needs file IO, raw SQL, subprocess or product internals, put that part in a ZODB Component — validated components execute unrestricted.

Component kinds

  • Module Component — module of helper functions/classes, imported as from erp5.component.module.X import ....
  • Extension Component — legacy single-function hooks (also usable as helpers).
  • Test Component — live tests, run via erp5_live_test.
  • Deploy with erp5_component_write (body_file + response sha256 proves byte-exactness); reset=true revalidates and reloads everything.

ModuleSecurityInfo is mandatory for restricted importers

Without it, the first import from a skin script or MCP tool fails with Unauthorized: import of 'erp5.component.module.erp5_version.X' is unauthorized — even though the module loads fine; AccessControl simply does not know it may be imported. The error names the versioned path (erp5_version) and hides the real cause. Fix at the top of the module:

from AccessControl.SecurityInfo import ModuleSecurityInfo
security = ModuleSecurityInfo(__name__)
for name in ('myHelper', 'myOtherHelper'):
  security.declarePublic(name)

Debugging load failures

  • The sandbox error never contains the real traceback. find_load_module logs it — read erp5_log_tail with grep/max_entries.
  • Real load errors (import-time exceptions) appear there as "Could not load Component module ...".

House pattern

The trusted module owns all filesystem / SQL / activity-queue work; the restricted tool body keeps validation, shaping and reporting (auditable, capped). Example on this instance: module.erp5.MCPDevHelpers (readFile/runSQL/activityStatus/drainActivities/scopedExport) behind the erp5_sql / erp5_activity_* / erp5_bt_commit tools.

Python 2.7 rules on this stack

  • Strings from ZODB/Localizer are native utf-8 str, from getHateoas they are unicode: isinstance(x, str) silently misses the latter — duck-type with hasattr(x, 'strip').
  • bool is a subclass of int: test isinstance(v, bool) before numeric handling.
  • json.dumps(ensure_ascii=False) on a str/unicode mix dies on the first umlaut — decode native str first (see _mcp_unicode in the existing tools).
  • Local syntax check without booting Zope: ~/srv/runner/software/d363c3c396fea8ff52302e30a6b90fcb/bin/python -m py_compile file.py; for script bodies wrap them in a function first (top-level return is Zope-legal only).

One-shot trusted glue: erp5_trusted_exec

For a single trusted operation (a private method call, upgradeSchema(), manage_addZSQLMethod, a bulk reindex loop) there is no need to bootstrap a component + External Method by hand any more: erp5_trusted_exec(source, function="run", args_json="[...]", kwargs_json="{...}") deploys the payload as a temporary Extension Component (reference MCPTrustedExec_<sha-of-source> — identical payloads reuse the same component, so re-runs are idempotent), wires an External Method into portal_skins/custom, invokes the function with the ERP5 site as first argument (name the parameter anything but self — JSON args bind from the 2nd parameter on) and deletes both artifacts again — unless keep=true (then the ids are returned). Error ⇒ the transaction is aborted: nothing the function did is persisted and no temp artifact is left behind. For a persistent trusted helper module, still use erp5_component_write as above.

  • custom[ext_id].__of__(portal) is refused by the restricted sandbox for ExternalMethod instances ("not allowed to access '__of__' in this context").
  • Never resolve a just-added skin object through getattr(portal, id) inside the request that created it: the per-process skin location cache does not know it, and priming that cache (initializeCache) there can wedge a Zope thread for hours. Bind through the folder (getattr(portal.portal_skins.custom, id)) — which is exactly what erp5_trusted_exec does, and pass the portal explicitly.
