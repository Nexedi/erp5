Token and output discipline for dev sessions

A tool result is re-sent to the model on every following turn, so its cost is size × remaining conversation, not size. In a measured session, shell output alone was 65% of the whole context bill. Small outputs beat fewer calls.

Output rules

  • Cap every shell command: git --stat, LIMIT n, | head. Never cat or re-print what is already known.
  • Emit verdicts, not payload dumps: after a call, report status/counts and only the lines that changed the decision.
  • erp5_live_test is verdict-only by default — keep it that way; full_output only when a failure needs reading.
  • erp5_sql: prefer format="count" or "summary"; "rows" only when the rows are the answer. Row cap is max_rows.
  • erp5_bt_commit on big BTs: summary_only=true and max_list; scope with path_pattern so the lists only contain your files.
  • Queue checks go through erp5_activity_status (a summary), not SQL against message_queue.

Payload rules (no code through tool arguments)

  • Never inline a payload over ~2 KB. Two safe paths: (1) body_file on erp5_component_write/erp5_skin_write — the server reads the local file and returns sha256/length to prove byte-exact deployment; (2) edit the BT's repository files and apply with erp5_bt_update_from_repository.
  • Verify deploys by hash, never by re-reading the source into the conversation.
  • Prefer one composite trusted helper call that returns counts over several round trips returning rows.

Measure it

./token_report.py (in woelfel-dev) parses the pi session log and ranks tools by weighted context cost (size × remaining turns). Run it before/after a change in habits: the bash share is the number to move. Before starting a long session, skim the last one's top offenders.

When debugging anyway

  • Ask for the tail, not the transcript: erp5_log_tail with grep and a bounded max_entries.
  • One probe script that prints a verdict (counts + the 3 decisive lines) instead of a sequence of exploratory calls.
  • Clean up probes in the same session; leftover zz_* scripts belong to earlier sessions — leave them unless they break something.
